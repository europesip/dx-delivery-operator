# Funciones, recurso a recurso

[English](features.md) · **Español**


| Recurso | Qué hace el operador |
|---|---|
| **DXConnection** | Comprueba que DX responde y acepta las credenciales (un Secret y, si hace falta, una CA). La comparten los recursos de un namespace; fija cada cuánto se revisa todo contra DX (`resyncInterval`) |
| **DXScriptApplication** | Toma los ficheros compilados de una **imagen OCI** (leída directamente del registro: no se ejecuta nada), de un **ConfigMap** o de una **URL** de un archivo; sustituye los `${NOMBRE}` (valores, ConfigMaps, Secrets, URL de ficheros del DAM); comprueba los límites de WCM; **hace el push** con DXClient solo cuando algo cambió; la restaura si se **borró o editó en DX**; la quita de DX al borrarla si se pide |
| **DXPage** | Crea la página con sus Script Applications (XMLAccess): títulos por idioma, acceso, tema, posición. Conserva el layout y los ajustes que la gente haga en ella entre actualizaciones; la **vuelve a crear** si se borró en DX |
| **DXDamCollection** | Crea la colección y sube cada fichero de su origen; un fichero cambiado pasa a ser **una versión nueva del mismo asset** (misma URL); restaura los borrados; acceso público o de usuarios autenticados; limpieza opcional |
| **DXTheme** | Un **tema**: sube al almacén WebDAV los ficheros de su origen (un tema propio completo, como el [tema de ejemplo de EUROPESIP](https://github.com/europesip/hcl-dx-theme-sample), o ficheros que se añaden a una copia de un tema del mismo DX), HTML opcional en el `<head>` de sus plantillas, y lo registra con XMLAccess. Las páginas lo usan con `spec.theme`; se restaura si se borra su registro o su carpeta en DX |
| **DXDatabase** | Crea la base de datos de un backend y su propietario en un **PostgreSQL, Oracle o SQL Server** existente, y escribe un **Secret** para el backend (`uri`, `jdbcUrl`, usuario, contraseña...). La contraseña se genera una vez y se conserva |
| **DXWCMLibraryImport** | **Importa bibliotecas WCM** de un export de bibliotecas (`ConfigEngine export-wcm-data` de un portal tradicional, o el módulo de datos de WCM de DX Compose: sin ConfigEngine) en el portal base o en un **portal virtual** (lo crea si se pide). Desde una URL o un registro (el fichero tal cual, subido con ORAS); selección por título, bibliotecas existentes y **Portal Site** protegidas salvo que se pida, **lotes** automáticos (límites de 500 MB y 20 minutos de DX), inventario con `dryRun`, roles en las bibliotecas importadas. **Una sola vez**: importa cuando cambia el recurso y nunca restaura ni borra contenido |
| **DXWCMLibraryExport** | **Exporta bibliotecas WCM** de un portal DX Compose (base o virtual) a un **artefacto OCI** (Harbor): el zip tal cual lo escribe DX más `EXPORT-INFO.txt` (servidor de origen, build de DX, fecha, bibliotecas). Se importa con `DXWCMLibraryImport` en otro DX Compose, o con `import-wcm-data` de ConfigEngine en un DX tradicional. **Una sola vez** |
| **DXExport** | **Paquetes portables**: páginas (XMLAccess), la biblioteca Portal Site y bibliotecas WCM de un portal DX Compose en **un artefacto OCI** (`dx-bundle/v1`), cada fichero en el formato nativo de DX, con `EXPORT-INFO.txt` y `bundle.json` (pasos de importación). Se importa en otro DX Compose (`DXXMLAccess`, `DXWCMLibraryImport`) o en un **DX tradicional sobre WebSphere** (`xmlaccess.sh`, `import-wcm-data` de ConfigEngine). Ver [Paquetes portables](portable-bundles.es.md). **Una sola vez** |
| **DXXMLAccess** | **Ejecuta peticiones XMLAccess** propias contra el portal base o un portal virtual: en línea, o los ficheros `.xml` de un archivo por URL (por ejemplo una carpeta de un repositorio Git), de un registro (ORAS) o de un ConfigMap, con variables `${NOMBRE}`. Se comprueban todos los ficheros antes de enviar nada; resultado por petición en el status y las respuestas de DX (exports) en un ConfigMap. **Una vez por cambio**, como un Job; petición de `cleanup` opcional al borrarlo |
| **DXJavaExtension** | **Java propio en DX Compose sin imagen propia** (0.14.0): un **portlet** JSR 168/286 (WAR) o **JAR de librería compartida** desde un artefacto OCI, cargado sobre la imagen **oficial** del Web Engine por un init container que el webhook de admisión del operador añade al pod del Web Engine. Resuelve la etiqueta a un digest **antes** de reiniciar nada (una etiqueta que no existe nunca reinicia el portal), reinicia el Web Engine pod a pod, registra los portlets en DX con XMLAccess `predeployed` **solo si faltan**, página opcional, vuelta atrás si falla. Exige que el cliente tenga derecho al **Java Transition Module** (JTM) de HCL. Mira [Extensiones Java](java-extensions.es.md) |
| **DXWCMAdminTask** | **Módulos de mantenimiento de WCM**: el **member fixer** (usuarios y grupos a los que apuntan los elementos) y el **workflow checker** (seguridad de los flujos, acciones pendientes, elementos sin flujo), el `ConfigEngine run-wcm-admin-task-*` del DX tradicional, por HTTP. **Modo informe** salvo `fix: true`; resumen en el estado, la respuesta de DX en un ConfigMap. **Una vez** |

Y en todos los recursos: **dependencias** (`dependsOn`: Deployments, StatefulSets, Jobs y los demás recursos; no
se sube nada hasta que el backend está listo), **política de deriva** (`Restore`, por defecto, o `Report`),
**política de borrado** (`Retain`, por defecto, o `Delete`), `suspend`, un **status** con condiciones, **eventos
de Kubernetes** de todo lo que hace en DX y una anotación para forzar una reconciliación al momento.
